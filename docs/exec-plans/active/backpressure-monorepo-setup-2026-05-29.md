# backpressure: Monorepo Setup Plan

## Goal

Scaffold the greenfield `backpressure` monorepo — MP's home for homegrown *backpressure* tooling (opinionated lint rules, shared TypeScript configs, and future guardrail tools) — into publishable pnpm-workspace packages, folding in the locked decisions from the effect-linting investigation plus MP's adopted cross-project stack best-practices. **v0 ships two packages:** `@mplibunao/oxlint-standards` (opinionated oxlint rule presets) and `@mplibunao/tsconfig` (strict shared tsconfig presets). End state: a monorepo that can author/test rules, lint and gate itself, and publish both packages to npm via OIDC trusted publishing. The charter is deliberately broader than lint + tsconfig (it accommodates future homegrown guardrail tooling), but v0 scope is hard-fenced to those two packages.

### oxlint JS-plugin authoring substrate (`references/oxc`, `references/vite-plus`)
- Rule shape: default-export `Plugin` with `meta.name` + `rules`; each rule is `{ meta?, create(context) { return { <ASTNodeType>(node) { context.report({ message|messageId, node }) } } } }`. ESTree-compatible AST node visitors; `node.range` carried automatically.
- Author with `@oxlint/plugins` (provides `definePlugin`/`defineRule`/`eslintCompatPlugin` + TS types `Context`, `Rule`, `Plugin`, `ESTree.*`). Context mirrors ESLint v9 RuleContext.
- **Avoid `createOnce`** (oxlint-only; breaks ESLint portability unless wrapped via `eslintCompatPlugin`). Use `create(context)` only for portable rules.
- Consumer config: `jsPlugins: ["@mplibunao/oxlint-standards"]` in `.oxlintrc.json` + enable `"<plugin>/<rule>": "error"`. Plugin-name resolution: `@scope/eslint-plugin-foo` → `@scope/foo`.
- **vite-plus integration:** `vp lint`/`vp check` invokes the real oxlint binary; when `lint` is set in `vite.config.ts` it prepends `-c <config>`. `jsPlugins` is part of `OxlintConfig` so it *can* live in vite.config, but path resolution for inline `jsPlugins` is untested — **safest for consumers is a standalone `.oxlintrc.json`** that oxlint discovers itself.
- **Constraint:** the oxlint JS-plugin API is **alpha, not semver-bound** (`"JS plugins are in alpha"`). TS plugins need Node ≥22.18/^20.19; ship compiled `.js` for safety.

### Cross-repo Effect recon (2026-05-30): patterns + guardrails

> Phase-2 explore-agent sweep across five community Effect repos added to the workspace (`references/effect-ts/{opencode,t3code,uploadthing,effect-solutions,effect-smol}`), plus a refresh of the port source. Goal: validate which rules are worth encoding (real-world patterns) and what guardrails/backpressure mechanisms to adopt — the same way executor was mined. Distilled evidence; raw transcripts not retained.

**Repo versions (the headline finding).** opencode (`effect@4.0.0-beta.66`), t3code (`4.0.0-beta.73`), effect-solutions (`4.0.0-beta.59`) and effect-smol (the v4 source itself) are **all Effect v4**; only uploadthing is v3 (`3.21.0`). **4 of 5 app repos are on v4, and v4 is a hard break** — `effect-smol/migration/*.md` documents wholesale renames. Rule-category risk ranking under v4 (effect-smol §3): **Schema HIGHEST** (moved into core; `filter→check`/`refine`, variadic→array ctors `Union([A,B])`/`Literals([...])`, `decode→decodeEffect`, `*FromSelf` suffix dropped), **Service/Layer VERY HIGH** (`Effect.Service`/`Context.Tag`/`GenericTag`/`Effect.Tag` all collapse to `Context.Service` with flipped arg order; `.Default` auto-layer + `dependencies` removed; `.layer` naming; `Layer.scoped→Layer.effect`), **Error HIGH** (`catchAll→catch`, `Either→Result`, `Cause` flattened, `*Exception→*Error`, `Schema.TaggedError→Schema.TaggedErrorClass`; **but `Data.TaggedError` is UNCHANGED**), **Composition MEDIUM** (gen/fnUntraced conceptually stable; combinator renames `zipRight→andThen`/`zipLeft→tap`/`async→callback`/`either→result`; `yield* ref|deferred|fiber` no longer valid), **Match LOWEST** (only `Match.either→Match.result`).

**Convergent patterns (→ candidate rules):**
- **gen-first is universal**, and the real unit of logic is **named `Effect.fn("Domain.method")`** (traced) + **`Effect.fnUntraced`** (internal). opencode 799 `fn`/`fnUntraced` vs 313 bare `gen`; t3code mid-migration (`docs/effect-fn-checklist.md`, 322 sites); effect-smol prefers `fnUntraced` over `()=>Effect.gen` (`.patterns/effect.md:62-79`); effect-solutions teaches `Effect.fn` for all named methods incl. nullary (`docs/04-services-and-layers.md:126`). → candidate `prefer-effect-fn` (flag `() => Effect.gen(...)` wrapper functions). Caveat: `.pipe()` *method* form dominates (t3code 2636 vs standalone `pipe()` 15); `flow()` + Config/Layer pipe-chains are sanctioned non-gen surfaces (uploadthing `config.ts`/`logger.ts`, effect-solutions `Effect.fn` 2nd arg) → gen-first rules must allowlist these or false-positive.
- **Namespace imports / ban the barrel `"effect"` import** — the single most-enforced convention across the ecosystem. uploadthing ESLint `no-restricted-imports` (`tooling/eslint-config/base.js:11-33`); t3code + effect-smol LSP `namespaceImportPackages`; effect-smol's own oxlint rule `effect/no-import-from-barrel-package`; opencode namespace-imports throughout. → top candidate `no-barrel-import`.
- **`no-inline-schema-compile`** (already an executor candidate in Item 10) is **independently shipped by t3code** as its sole custom oxlint rule (`oxlint-plugin-t3code/rules/no-inline-schema-compile.ts`, with colocated test) — forces `Schema.decode*`/`encode*` to module scope (perf). Confirmed high-value; doubles as substrate validation of the jsPlugins + RuleTester approach.

**Guardrail / backpressure mechanisms (what the user asked to mine):**
- **`@effect/language-service` is the real semantic guardrail in v4 repos** — t3code, effect-smol, effect-solutions, uploadthing all ship it. t3code runs it at `error` with a large diagnostic map (`tsconfig.base.json:21-55`): `importFromBarrel`, `missingEffectServiceDependency`, `leakingRequirements`, `unsafeEffectTypeAssertion`, `instanceOfSchema`, `globalDate/Random/Console/Fetch/Timers`, `preferSchemaOverJson`, `schemaSyncInEffect`, `cryptoRandomUUID`. **This overlaps heavily with the Rika `effect-*` semantic rules we planned to depend on (Item 16)** → resolved by Q2 → Branch B: delegate type-aware semantics to the LSP, no Rika dependency. Installed at build time via `effect-language-service patch` / `effect-tsgo patch` (a `prepare` script).
- **Custom oxlint plugins are the in-the-wild backpressure shape** (validates our whole approach): t3code (`oxlint-plugin-t3code`, jsPlugins-wired), effect-smol (`@effect/oxc` — `no-bigint-literals`, `no-import-from-barrel-package`, `no-js-extension-imports`, `no-opaque-instance-fields`, `jsdocs`), executor (already mined). opencode runs oxlint with **no custom Effect rules** — only noise-suppression tuning.
- **Preset must DISABLE oxlint rules that fight Effect** (convergent, concrete config): opencode + effect-smol both turn off **`require-yield`** (`function*` bodies don't always yield) and **`no-shadow`** (nested `function*` closures inherently shadow); effect-smol also disables `no-namespace`, `no-non-null-assertion`, `no-explicit-any`, `ban-ts-comment`. → our `effect` preset MUST ship these `off`, or it false-positives on idiomatic Effect everywhere.
- **Native rule tunings worth adopting** (effect-smol `packages/tools/oxc/oxlintrc.json`): `consistent-type-imports` with `inline-type-imports` + `no-import-type-side-effects` (pairs with `verbatimModuleSyntax`); `array-type: { default: generic }` (`Array<T>` not `T[]`); `no-console`, `no-var`, `no-unneeded-ternary`.
- **Other repo-hygiene gates seen** (for OUR repo, optional): madge circular-dep check (effect-smol), bundle-size diff (uploadthing/effect-smol), doc-typecheck harness (effect-solutions extracts every doc code block + `tsc`-checks it). Convergent CI order is **fmt → lint → typecheck → test**; lint-in-CI is mixed (opencode/effect-solutions don't gate lint — consistent with our "consumers decide CI wiring" stance).
- **Repo-local Effect skill validated**: opencode ships `.opencode/skills/effect/SKILL.md` — same shape as our planned `.claude/skills/` (Item 1).

**Corrections to existing planned rules (from real usage):**
- **`no-match-orelse` (force `Match.exhaustive`) is too aggressive** — Match is near-dead in 4/5 repos (≈1 occurrence each in opencode/t3code), and uploadthing/opencode intentionally end on `Match.orElse` (non-exhaustive). Dropped (Q3).
- **Do NOT blanket-ban `Data.TaggedError`** — t3code uses it deliberately for internal/in-process errors and reserves `Schema.TaggedErrorClass` for wire/contract errors (a *boundary split*, `packages/contracts` vs `apps/server`); `Data.TaggedError` is also v4-unchanged. Error-model rules (Item 14 executor twins) must respect this.
- **`prefer-yield-tagged-error`** (`yield* new Err()` over `yield* Effect.fail(new Err())`) is well-supported — opencode prescribes it (`AGENTS.md:97-98`) yet violates it 91× — a real lint target, keep it.

- **Port source refresh.** `biome-effect-linting-rules` pulled to **v0.0.6** (was v0.0.4-2): current baseline is 50 rules (the earlier investigation's "52" was a stale/miscounted pre-refresh figure), license/attribution unchanged (MIT © Roman Naumenko). Two core rules *refined* — fold into the port: `no-model-overlay-cast` now exempts `as const`; `no-switch-statement` now matches the full `switch` AST node (the old structural pattern missed cases, and the diagnostic span moved to the whole statement).

### Why Effect-by-default does NOT apply here
This repo is **lint tooling**, not an Effect application. Its source is AST-visitor rules (pure TS over ESTree), not domain/service/async logic. Per the stack-defaults Effect card's opt-out, plain strict TypeScript is correct; Effect is not adopted for the repo's own code.

## Approach

Scaffold the repo as the **`backpressure` pnpm 11 monorepo publishing two packages** (`packages/oxlint-standards/` first, then `packages/tsconfig/`), matching D1/D2. The ordering deliberately **proves the riskiest delivery path first**: implement one trivial source-derived rule (`no-effect-as`), then build → `npm pack` → install the tarball into a throwaway consumer → load it through oxlint `jsPlugins` → assert a real diagnostic. Only after that artifact smoke is green does the bulk 50-rule port begin. This validates package exports, compiled JS, plugin loading, attribution, and release mechanics before any effort is sunk into rule translation.

Two substrate hardenings happen in that same early window, before the bulk port: (a) pin the exact oxlint version and snapshot the alpha `jsPlugins` API surface the rules depend on (the API is explicitly not semver-bound); (b) lock the test runtime to oxlint's own `RuleTester` (`oxc/apps/oxlint/src-js/package/rule_tester.ts`), with ESLint `RuleTester` only as an optional portability cross-check, plus a real-oxlint fixture-replay harness so AST parity is proven across the whole catalog rather than discovered at publish. The GritQL→ESTree translation contract — including whether the loose `contains "effect"` file gate becomes a real import-binding check — is settled with the first rule, since it defines the shared import-guard helper most rules reuse.

The 2026-05-30 cross-repo recon resolved **three decisions at the mid-flow check-in** (evidence curated in Background): **Q1 → v4 primary** (rules target v4 identifiers); **Q2 → Branch B** — the pack ships fast AST-shape rules only and *delegates* type-aware semantics to `@effect/language-service` (documented + recommended to consumers, not shipped; no Rika dependency); **Q3 → drop `no-match-orelse`**. Settling these before the bulk port fixes identifier matching, preset ownership, and the semantic-guardrail boundary once. The translation contract (Item 6) pins the v0.0.6 source refresh and the v4 identifier sets (Schema HIGHEST risk, Service/Layer VERY HIGH, Error HIGH).

Decisions that stay locked and reflected throughout: **port the full catalog before the first npm publish** (pipeline proven locally early via the Item 7 pack-smoke); **one opinionated gen-first `effect` preset** (Item 17 — reconfirmed by all 5 recon repos: gen for logic, pipe for combinator tails); the plan lives in `docs/exec-plans/active/` per MP's docs IA; and **mutation testing is an agent-run workflow (orchestrator/worker, run via delegation)** — never wired into CI, but the v0 full sweep gates the first publish (Item 18). The recon also adds two convergent candidate rules (`prefer-effect-fn`, `no-barrel-import`), a required `effect`-preset noise-suppression config (`require-yield`/`no-shadow` off), and two corrections — never blanket-ban `Data.TaggedError`; keep `prefer-yield-tagged-error`. The repo is reframed as the **`backpressure` monorepo** (ADR 003): v0 = two packages (oxlint-standards, then tsconfig), Effect carve-outs confined to the `effect` preset (so non-Effect projects compose `general` + stack presets cleanly), and a charter broader than lint + tsconfig that does NOT expand v0 scope.
